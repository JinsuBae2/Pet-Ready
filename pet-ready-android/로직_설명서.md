# Pet Ready 앱 로직 설명서

## 1. 프로젝트 개요

**Pet Ready**는 로봇 강아지와 반려동물 생활을 시뮬레이션하는 Android 앱입니다.  
사용자가 로봇 기기를 등록하고, 일정 기간(1~3주) 동안 미션을 수행하며 점수를 관리합니다.

---

## 2. 전체 화면 흐름

```
MainActivity (로그인)
    ↓ 로그인 성공 후 GET device/my
    ├── 200: 등록 기기 정보 캐싱 후 QR 화면 생략
    └── 404: RobotConnectActivity (기기 연결 - QR 스캔)
                 ↓ 기기 등록 완료
SimulationSetupActivity (시뮬레이션 기간 설정 - 최초 1회)
    ↓ 설정 완료
DashboardActivity (메인 대시보드)
    ├── MissionActivity (미션 목록)
    │       ├── WalkActivity (산책 미션)
    │       ├── MissionDetailActivity (일반 미션 상세)
    │       └── MissionCompleteActivity / MissionProgressActivity
    ├── WalkActivity (산책)
    ├── ExpenseActivity (지출 관리)
    ├── ActivityLogActivity (활동 로그)
    ├── ReportActivity (점수 리포트)
    ├── PetSettingsActivity (펫 설정)
    └── MoreActivity (더 보기)
         └── FinalReportActivity (시뮬레이션 종료 리포트)
```

---

## 3. 로그인 / 인증 흐름 (MainActivity)

1. 앱 시작 시 FCM(Firebase) 알림 권한 요청 (Android 13+)
2. Firebase에서 FCM 토큰을 가져와 로컬에 저장
3. **로그인 버튼** 클릭 시:
   - 이메일/비밀번호 입력값 검증
   - FCM 토큰을 포함해 `POST auth/login` API 호출
   - 성공 시 `accessToken`, `refreshToken`을 SharedPreferences에 저장
   - JWT를 담아 `GET device/my` API 호출
   - `200 OK`: 응답의 `deviceId`, `petName`을 로컬에 동기화하고 기기 연결 화면 생략
   - 기간 설정 완료 상태이면 `DashboardActivity`, 미완료 상태이면 `SimulationSetupActivity`로 이동
   - `404 Not Found`: 등록 기기가 없는 신규 사용자로 판단해 `RobotConnectActivity`로 이동
   - 그 외 오류/통신 실패: QR 화면으로 잘못 보내지 않고 로그인 화면에서 오류 표시
4. **회원가입** 버튼: `RegisterActivity`로 이동

---

## 4. 기기 연결 (RobotConnectActivity)

1. `GET device/my`가 `404 Not Found`인 기기 미등록 사용자만 거치는 화면
2. **QR 스캔**으로 로봇 기기 ID를 등록:
   - `PETREADY-` 또는 `DOG-` 접두어를 서버 기기 ID 형식으로 정규화
   - `POST device/register` API로 서버에 등록
3. 등록 완료 후 → 시뮬레이션 설정 여부 확인:
   - 미설정 → `SimulationSetupActivity`
   - 설정 완료 → `DashboardActivity`
4. 실제 서버에서 기기 등록이 완료되면 초기 양육비 150,420원이 자동 적재:
   - 가상 유기견 입양비 100,000원
   - 개 종합백신 25,992원
   - 광견병 백신 24,428원

## 5. 시뮬레이션 관리 (SimulationRepository)

| 항목 | 내용 |
|------|------|
| 기간 | 1~3주 선택 (기본 3주) |
| 저장소 | SharedPreferences `pet_ready_simulation` |
| 현재 일차 | 시작일로부터 경과 일수 + 1 |
| 종료 판단 | `현재 일차 > 총 일수` |

**Dashboard 진입 시 체크:**
- 시뮬레이션 미설정 → SimulationSetup으로 강제 이동
- 시뮬레이션 종료됨 → FinalReport로 강제 이동
- 정상 → 펫 상태 / 점수 / 진행 일차 표시

---

## 6. 펫 상태 관리 (CareStatusRepository)

저장소: SharedPreferences `pet_ready_care_status`

### 초기값
| 항목 | 초기값 |
|------|--------|
| 배터리 | 100 |
| 배고픔 | 100 (높을수록 포만감 있음) |
| 친밀도 | 30 |

### 시간 경과 감소 (applyTimeDecay)
- **배터리**: 1시간마다 -1
- **배고픔**: 12시간을 주기로 최대 -50 (식사 주기 기준)
  - 경과 시간 / 12h × 50 으로 계산
- `getStatus()` 호출 시마다 경과 시간만큼 감소 적용

### 상태 변화 이벤트
| 이벤트 | 변화 |
|--------|------|
| 밥주기 미션 완료 | 배고픔 100으로 리셋 |
| 미션 완료 (모든 종류) | 친밀도 +3 |

## 7. 미션 시스템 (MissionRepository + MissionActivity)

### 미션 종류
| 타입 | 설명 | 긴급 여부 |
|------|------|-----------|
| `WALK` | 산책 미션 | - |
| `FEEDING_TIME` | 밥주기 미션 | 긴급 |
| `BARKING_ALERT` | 짖음 알림 대응 | 긴급 |
| `CARE` | 일반 돌봄 | - |
| `VET_CHECK` | 동물병원 진료 | - |
| `VACCINATION` | 예방접종 | - |
| `ROBOT_PLAY` | 로봇 상호작용 | - |
| `EMERGENCY` | 긴급 상황 | 긴급 |

### 미션 로딩
- 실제 로그인: `GET mission/today`로 로그인 사용자의 오늘 미션 조회
- 당일 일일 미션이 없으면 서버가 `WALK`, `FEEDING`, `ROBOT_PLAY` 3종을 자동 생성
- 대시보드 진입 시 미션 API를 먼저 호출해 전체/완료 개수를 요약 표시
- 미션 화면에서 `WALK`, `FEEDING`, `ROBOT_PLAY`, `BARKING_ALERT`, `MEDICAL` 타입별 문구 표시
- 모든 미션 완료는 `POST mission/{id}/complete`로 서버에 반영
- `MEDICAL` 완료 시 백엔드가 진료비 1~2개 항목을 영수증 총액에 자동 가산
- API 오류와 정상 빈 목록은 서로 다른 메시지로 표시
- 미션 상세 화면에서 `POST mission/{id}/start` 호출 후 상태를 `진행 중`으로 변경
- 진행 중에는 `GET mission/{id}`를 3초 간격으로 조회해 서버 완료/실패 상태 확인
- 서버의 `MISSION_COMPLETED` FCM 수신 시 성공 알림을 표시하고 열린 상세 화면을 완료 처리

### 미션 완료 처리
1. **산책 미션**: `WalkActivity`로 이동, 10분 이상 산책 시 자동 완료
2. **밥주기 미션**: `POST pet/feed` API로 앱 터치 상태를 기록하고 Jetson 밥그릇 인식 후 서버에서 완료
3. **일반 미션**: `POST mission/{id}/complete` API 호출

### 미션 완료 시 연쇄 효과
- 점수 적용 (`ScoreRepository.applyMissionCompleted`)
- 지출 기록 (`ExpenseRepository`)
- 밥주기 미션이면 배고픔 리셋
- 친밀도 +3
- 활동 로그 추가

## 8. 산책 시스템 (WalkActivity)

1. 위치 권한(ACCESS_FINE_LOCATION) 요청
2. Google Maps + FusedLocationProvider로 실시간 경로 추적
   - 위치 업데이트 주기: 3초 (최소 1초)
3. 타이머가 1초마다 화면 갱신
4. **종료 시** 처리:
   - 이동 거리 / 소요 시간 계산
   - 10분(600초) 이상이면 산책 미션 완료로 저장
   - `ScoreRepository.applyWalkCompleted` 호출
   - `POST walk/end` API로 서버에 기록 전송
   - 활동 로그 추가

## 9. 점수 시스템 (ScoreRepository)

저장소: SharedPreferences `pet_ready_score`  
초기 점수: **100점** (모든 항목)

### 점수 항목
- **종합 점수** (`current_score`)
- **돌봄 점수** (`care_score`): 밥주기, 병원, 접종 미션
- **산책 점수** (`walk_score`)
- **미션 점수** (`mission_score`): 일반 미션

### 산책 점수 변화
| 달성률 | 이벤트 | 점수 변화 |
|--------|--------|-----------|
| 2km 이상 (100%) | WALK_FULL | +5 |
| 1.4km~2km (70~99%) | WALK_PARTIAL_HIGH | +2 |
| 600m~1.4km (30~69%) | WALK_PARTIAL_LOW | -3 |
| 600m 미만 (30% 미만) | WALK_NONE | -5 |

### 미션 응답 시간 점수 변화
| 응답 시간 | 이벤트 | 점수 변화 |
|-----------|--------|-----------|
| 5분 이하 | MISSION_FAST_COMPLETE | +5 |
| 5~15분 | MISSION_NORMAL_COMPLETE | +2 |
| 15~30분 | MISSION_LATE_COMPLETE | -3 |
| 30분 초과 | MISSION_NO_RESPONSE | -10 |
| 응답시간 없음 (밥주기) | FEED_ON_TIME | +3 |
| 응답시간 없음 (일반) | MISSION_NORMAL_COMPLETE | +2 |

모든 점수는 **0~100** 범위로 제한됨.

## 10. FCM 푸시 알림 (PetFirebaseMessagingService)

- 서버에서 미션 알림이 오면 Firebase FCM으로 수신
- **앱 포그라운드**: `UrgentMissionActivity` 즉시 실행
- **앱 백그라운드**: 시스템 알림 표시, 탭하면 `UrgentMissionActivity` 실행
- 알림 데이터에서 `missionId`, `missionType`, `title`, `message` 파싱

## 11. 주요 Repository 목록

| Repository | 역할 | 저장소 |
|------------|------|--------|
| `AuthRepository` | 로그인 토큰 저장/조회 | SharedPreferences |
| `FcmTokenRepository` | FCM 토큰 저장 | SharedPreferences |
| `DeviceRepository` | 등록된 기기 ID 저장 | SharedPreferences |
| `SimulationRepository` | 시뮬레이션 기간/진행 관리 | SharedPreferences |
| `CareStatusRepository` | 배터리/배고픔/친밀도 관리 | SharedPreferences |
| `ScoreRepository` | 점수 계산 및 이벤트 기록 | SharedPreferences |
| `MissionRepository` | 미션 목록/완료 처리 | SharedPreferences + API |
| `WalkRepository` | 산책 결과 서버 전송 | API |
| `ActivityLogRepository` | 활동 로그 기록 | SharedPreferences |
| `ExpenseRepository` | 지출 항목 기록 | SharedPreferences |
| `PetProfileRepository` | 펫 이름/아바타/사진 저장 | SharedPreferences |

## 12. API 엔드포인트 요약

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `auth/login` | 로그인 (FCM 토큰 포함) |
| POST | `auth/register` | 회원가입 |
| POST | `device/register` | 기기 등록 |
| GET | `device/my` | 로그인 사용자의 등록 기기 및 펫 정보 조회 |
| POST | `pet/status` | 펫 상태 전송 |
| POST | `pet/feed` | 밥주기 |
| POST | `walk/end` | 산책 종료 기록 |
| POST | `mission/{id}/complete` | 미션 완료 |
| GET | `mission/today` | 오늘 미션 목록 조회 |
| PATCH | `device/pet-name` | 펫 이름 변경 |
| GET | `dashboard/{deviceId}` | 실시간 점수/최근 이벤트 조회 |
| GET | `report/final` | AI 분석 기반 최종 리포트 조회 |
